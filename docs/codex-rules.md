# Правила работы Codex

1. Не делать большие изменения без необходимости.
2. Перед изменением кода кратко объяснять план.
3. После изменения перечислять изменённые файлы.
4. Не удалять существующий функционал без причины.
5. Не хранить секретные ключи в коде.
6. Все переменные окружения хранить в .env.local.
7. Сначала делать простую рабочую версию, потом улучшать дизайн.
8. Все таблицы Supabase описывать SQL-миграциями.
9. Не превращать проект в одну большую таблицу.
10. Ручные заглушки должны быть отдельной логикой, а не просто комментарием.
